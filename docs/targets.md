# Targets

Target curves share the `ResponseCurve` foundation with measurements — one
set of frequency/gain logic, no duplication.

## Kinds

- `builtin-flat`: constant 0 dB reference, owned by this repo, always present.
- `parametric`: generated by the bass-shelf + treble-tilt + offset builder
  (pure math, stored with its params so edits regenerate). No data needed.
- `imported`: user CSV files via the same parser/preview flow as measurements.

Third-party targets (Harman, JM-1, diffuse-field, …) are **not bundled** —
see `docs/measurement-data-licenses.md` for the per-source verdicts. The UI
points outward; users import what they may legally use.

## No correctness claims

No target is presented as objectively correct. The UI always labels which
target is active, and measurement/target/correction stay visually distinct.

## Editor

Only mathematically defined controls ship: bass shelf (gain + midpoint),
tilt (dB/octave + pivot), global offset — each with a live preview graph.
Point editing is deferred until Phase 7 defines how edits interact with
fitting ranges.

## Custom targets

Create (builder or import), rename via edit-and-save, delete. Persisted in
IndexedDB alongside measurements; profiles reference them by id.
